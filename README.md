# Conversation Lab

[실행 사이트](https://junwon-conversation-lab.streamlit.app/) · [Notion 보고서](https://app.notion.com/p/41cd259f3ec781d2a072c3bc566fafd3?pvs=204) · [검증 기록](docs/verification.md)

서준원 · 동아대학교 조선해양공학과 · 데이터처리개론

기존 회귀·인공신경망 분석 프로그램을 바탕으로 자유 대화와 인터넷 검색을 추가한 독립 프로젝트다. 기존 `data-analyzer` 저장소와 두 Streamlit 앱, 이전 Notion 보고서는 수정하지 않는다.

## 사용 방법

1. 인터넷 ON에서 궁금한 내용을 편하게 입력한다. 첫 일반 대화에는 약 1.28 GB 공개 모델을 서버에 다운로드하고 무결성을 확인한다.
2. `배가 물에 뜨는 원리를 검색해서 설명해줘`처럼 질문하면 관련 자료를 찾고 답변 아래 출처·확인 시각을 표시한다.
3. `더 쉽게 설명해줘`, `방금 내용을 세 줄로 줄여줘`처럼 대화를 이어간다.
4. 인터넷 OFF에서는 외부 검색과 새 모델 다운로드가 차단된다. 기존 분석 명령은 모델 설치 없이도 동작한다. 모델을 준비했다면 OFF에서도 일반 대화를 생성한다.
5. `새 대화 시작`으로 대화·입력 데이터·실험 기록을 초기화한다. 인터넷 스위치 설정은 유지된다.

인터넷 스위치는 **앱의 외부 접근**을 제어한다. PC의 Wi-Fi를 변경하지 않는다. Streamlit 웹사이트 접속에는 인터넷이 필요하다. 기기의 인터넷이 완전히 끊긴 상태에서는 아래 방법으로 PC에서 로컬 실행한다. 진행 중인 요청은 완료된 후 스위치 변경이 반영된다.

## OFF에서도 가능한 분석

- `선형회귀 해줘` / `비선형회귀 해줘` / `신경망 학습해줘`
- `모델 3가지 비교해줘` / `3차 다항식으로 해줘`
- `이전 결과 보여줘` / `오차가 큰 예측 10개 보여줘` / `보고서 만들어줘`
- `x: 1,2,3,4,5,6 y: 5,7,9,11,13,15 선형회귀 해줘`
- 위 데이터 분석 후 `x가 10일 때 예측해줘` → 선형 모델 예측 23
- `데이터 입력` 다음 줄부터 CSV 또는 탭 구분 표(30~1000행). 마지막 열이 목표값이다.
- `예측: x=12` 또는 여러 입력 열의 값을 쉼표로 연결한다.
- `기본 데이터 사용`으로 공개 선체 저항 데이터로 돌아간다.

숫자 목록은 6~1000쌍을 받는다. 30개 미만은 교차검증을 사용하며, 작은 표본의 점수가 일반화를 보장하지 않는다.

## 설치와 실행

Python 3.12, Linux x86_64 CPU 기준:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

인터넷이 끊기기 전에 패키지를 설치한다. 자유 대화도 OFF에서 쓰려면 ON에서 한 번 대화해 모델을 준비한다. 분석 전용 OFF 사용에는 LLM 파일이 필요 없다. `.models` 폴더를 삭제하면 다시 다운로드해야 한다.

Windows/macOS에서는 `requirements.txt`의 Linux용 llama-cpp-python wheel 한 줄을 해당 운영체제의 공식 설치 방법에 맞춰 교체해야 한다. 이 환경은 직접 검증하지 않았다.

```bash
pip install -r requirements-dev.txt
python -m pytest tests -q
```

Streamlit Community Cloud에는 **이 새 저장소**의 `main`, `app.py`, Python 3.12를 지정한다. 유료 추론 API와 API 키는 사용하지 않는다. 모델 파일은 GitHub에 올리지 않고 최초 사용 시 Hugging Face에 공개된 Qwen3 양자화 파일에서 다운로드한다.

## 동작 원리

채팅 입력 → 정확한 기존 명령 확인 → 해당하면 Python 계산 → 그 외에는 Qwen의 요청 해석 → 필요 시 웹 검색 → 최근 대화·실제 계산 결과·검색 자료를 넣어 답변 생성.

- **대화**: Qwen3-1.7B, Q4_K_M 양자화, llama-cpp-python CPU 추론. 기존의 1~2문장 제한을 없애고 최근 최대 12개 메시지를 토큰 한도 내에서 참고한다.
- **검색**: DDGS가 현재 사용 가능한 공개 검색 제공자를 선택한다. 제공자별 제한 시간은 8초이며 검색이 실패하면 그 사실을 표시한다. 최대 3개 자료, 상위 2개 페이지 본문 일부만 읽는다. 본문을 읽지 못하면 검색 요약이라고 표시한다.
- **기억**: 같은 세션의 최근 메시지와 직전 검색 자료를 참고한다. 웹 자료를 이용하는 것은 검색 증강 생성(RAG)이며 모델 가중치의 자동 재학습은 아니다.
- **회귀**: 선형회귀는 잔차제곱합을 최소화한다. 비선형 입력 관계에는 2·3차 다항 특성과 Ridge 규제를 사용한다. 다항회귀는 입력에 비선형이고 계수에는 선형이다.
- **인공신경망**: 기본 공개 데이터는 8→64→32→16→1, ReLU, Adam, 학습률 0.001. 검증 오차로 가중치를 선택한다.
- **검증**: 기본 데이터는 같은 선박이 섞이지 않도록 그룹별로 분할한다. 스케일러는 학습 데이터에만 적합한다. 모델 선택은 검증 지표로 하고 테스트 지표는 별도 표시한다.
- **안전한 실행**: LLM은 허용된 동작 이름만 선택한다. 생성 코드의 `eval`/`exec` 실행은 없으며 예측 숫자는 직접 입력한 값만 파싱한다. 검색 페이지 안의 명령은 실행하지 않는다.

## 데이터

Caprace·Fahrnholz, *Sailboat Hull Resistance Dataset and Predictive Model*, v4, CC BY 4.0. 기존 과제의 한글 열 이름 정리본 1,018행·70개 선형을 동봉했다. 출처: https://doi.org/10.17632/gw23dgzn6h.4

입력은 Fn, Rn, Cp, Cb, Cw, L/B, B/T, LCB/L이고 목표는 **Rt/Δ × 10³(정규화 저항)**이다. N 단위의 저항으로 해석하면 안 된다. 사용자가 입력한 데이터의 단위는 사용자가 정한 단위를 따른다.

## 구조

`app.py` 진입점, `conversation/ui.py` 대화 화면·상태 스위치, `conversation/engine.py` 요청 처리, `conversation/model.py` 공개 LLM, `conversation/web.py` 인터넷 정책·검색, `conversation/plots.py` 결과 그래프. 기존 계산은 `llm_lab/analysis.py`, `llm_lab/small_sample.py`, `models/neural_network.py`, `core/`를 재사용한다.

## 한계와 확인 사항

무료 CPU의 소형 모델이므로 대형 상용 챗봇 수준의 추론 정확도나 응답 속도를 보장하지 않는다. 검색 자료를 잘못 요약하거나 질문 의도를 잘못 분류할 수 있다. 검색·네트워크 실패는 화면에 표시하고 최신 정보를 확인했다고 주장하지 않는다. 인터넷 ON은 모든 사이트의 접속 성공을 뜻하지 않는다. 30초 간격 연결 확인과 질문별 검색 결과를 구분해 표시한다.

대화·실험 기록은 서버의 세션 파일에 임시 저장되며 다른 사용자와 공유하지 않는다. 재접속·서버 재시작 시 화면의 대화가 유지되지 않을 수 있다. 검색 질문은 검색 서비스에 전송되므로 개인 식별정보나 비밀정보를 검색 문구로 넣지 않는다. 무료 서버가 잠들거나 자원이 부족하면 시작·응답이 지연될 수 있다.

실제 검증 결과와 실행 화면은 `docs/verification.md`에 기록한다. 검증 전의 성공 수치를 만들지 않는다.

## 강의와 연결

`2026. 11. 6. 데이터처리개론.txt` 39:13~40:52에는 공개 LLM을 선택·다운로드·설치하고 웹사이트에 대화창을 붙이는 과제가 설명되어 있다. 10:38~12:37은 데이터 분할, 42:43 이후는 개별 수치 예측의 오차를 다룬다. 인터넷 ON/OFF와 웹 검색은 이번 사용자 요청에 따른 확장이다. 녹취 텍스트를 확인했으며 음성을 직접 청취한 기록은 아니다.

## AI 활용과 설명할 질문

사용자가 대화 중심 UI, ON/OFF, 기존 기능 유지와 과제 독립을 요구했다. AI가 구현·오류 수정·검증 코드·문서 초안을 작성했다. 자동 실행 결과와 실제 브라우저 관찰을 구분해 기록하며 사용자가 직접 수행하지 않은 시험·소감을 작성하지 않는다.

1. 인터넷 검색과 LLM 가중치 학습은 어떻게 다른가?
2. OFF에서도 회귀와 신경망 계산이 가능한 이유는 무엇인가?
3. 계산 결과와 LLM이 생성한 설명을 왜 구분해야 하는가?
4. 같은 선박의 데이터를 학습·테스트에 섞으면 어떤 문제가 생기는가?
5. 검색 출처가 있더라도 답변을 그대로 믿으면 안 되는 이유는 무엇인가?
